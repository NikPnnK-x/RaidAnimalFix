[b]3.0.926.0[/b]

[list]
[*] Multithreaded pathfinding is now deterministic on every map tick. RimWorld 1.6 computes paths on worker threads: PathGridDoorsBlockedJob is scheduled at the end of MapPreTick and reads live pawn positions while the main thread is already writing them in PatherTick. Who wins depends on the thread scheduler, so two machines get different blocked cells, a different A* path and a different next cell. Multiplayer knows this and forces the jobs to finish, but only for a map's own tick; with async time maps are also ticked from the world pass, and there the jobs were left running. We now force them to finish after every MapPreTick, whichever side it came from.
[*] Desync reports now record why a path failed: the cell, the blocking edifice, the pawns standing in it, the cached collision flag and the path node count. Until now the reports only showed the consequence — one side had spent an extra roll on a new job id.
[*] The host writes a by-name snapshot too. The host never gets the desync window, so its snapshot stayed from an earlier session and there was nothing to compare against. It is now written when a client starts re-joining, and the in-memory ring was enlarged to survive that delay.
[/list]

[b]Reminder: all players, host included, must run the same version.[/b]

[b]3.0.926.0 (по-русски)[/b]

[list]
[*] Многопоточный поиск пути теперь детерминирован на каждом тике карты. В 1.6 путь считается на рабочих потоках: PathGridDoorsBlockedJob ставится в конце MapPreTick и читает живые позиции пешек, пока главный поток их уже переписывает в PatherTick. Кто успел раньше — решает планировщик потоков, поэтому у двух машин разные заблокированные клетки, разный путь A* и разная следующая клетка. [*] В отчёт о рассинхроне пишется причина срыва пути: клетка, стоящая в ней постройка, пешки на ней, кешированный признак столкновения и остаток узлов. До сих пор отчёты показывали только следствие — одна сторона потратила лишний бросок на новый номер работы.
[*] Хост тоже пишет поимённый снимок. Окна рассинхрона хост не получает, поэтому его снимок оставался от прошлой сессии и сравнивать было нечего. Теперь он пишется, когда клиент начинает перезаходить, а кольцо в памяти увеличено, чтобы пережить эту задержку.
[/list]

[b]3.0.923.0[/b]

[list]
[*] Fixed: quests stopped appearing. The colony-age override was applied to TickManager.TicksSinceSettle, which IncidentCycleUtility divides by 1000 to get the interval index of an incident. An incident only fires on an exact index match, and the storyteller is ticked on the world clock, so the index must advance by exactly one per storyteller tick. Feeding it map time, which runs several times faster than world time in async mode, made the index jump by two or three and skip most hits. Quests, with a single hit per 40-day cycle, were hit hardest. The override now targets GenDate.TicksSinceSettle, which only feeds minDaysPassed and threat-point scaling, and leaves the incident cycle on the world clock.
[*] Removed the "hide other players' quests" filter. Multiplayer already does this, with a toggle button and an owner colour stripe. Our version used a worse ownership rule and ignored that toggle, so quests stayed hidden even with "All quests" selected.
[/list]

[b]Reminder: all players, host included, must run the same version.[/b]
